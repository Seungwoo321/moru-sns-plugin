# 형식 선택과 반응 검토

## 근거를 먼저 구분

- 현재 운영 문서에 정리된 공식 가이드와 직접 확인한 원게시물·작성자 기록을 우선 읽어라. 레퍼런스별 출처·플랫폼·형식·관찰 날짜·확인된 사실·적용할 요소·한계를 남겨라. 계정별 사례 URL이나 콘텐츠를 이 스킬에 고정하지 마라.
- 공식 기능 지원, 관측된 사례의 구성, 작성자의 성과 자기보고, 우리 계정에서 관찰한 반응, 운영자가 제안한 실험을 구분하라. 성공 사례를 재현 보장이나 AI 운영 성과로 바꾸지 마라.
- 아래 표는 소재를 설명하기 위한 편집 선택지다. 특정 형식의 성공 사례를 확인하지 못했으면 편집 제안이라고 표시하고, 확인한 것처럼 이름·수치·출처를 만들지 마라.

## 소재별 형식 선택

| 선택지 | 채택할 조건 | 구성·한계 |
| --- | --- | --- |
| Threads 텍스트 원글 | 관찰·선택·배움이 글만으로 유용하고 독립적으로 이해됨 | 짧더라도 구체적인 사실·맥락을 담고 미디어를 의무화하지 않음 |
| 개발 팁·짧은 설명 | 실제로 확인한 방법, 재현 조건, 적용 범위나 제한이 있음 | 보편적 해결책처럼 과장하지 않고 필요한 기술 용어만 설명. 검증되지 않은 팁은 가설로 구분 |
| 원글 + 본인 후속 댓글 | 원글만으로 핵심이 성립하고 추가 정보가 독립적으로 유용함 | 각 후속에 재현 절차·세부 설명·한계 등 새 정보. 예고만 남기거나 반응 수를 위해 분할하지 않음. 실제 발행은 자기 원글 소유·성공 기록·개별 작업 ID와 부분 실패 규칙을 따름 |
| 한 장 또는 여러 스크린샷 + 설명 | 정지 화면·전후 상태·UI의 구체적 차이를 비교해야 이해가 쉬움 | 이미지별 공개 범위·순서·설명을 확인. 동일 조건의 실제 자료인지 구분하고, 현행 발행 도구의 이미지/다중 이미지 지원과 별도 확인 |
| Threads 영상 또는 Instagram Reels | 동작·흐름·시간에 따른 변화가 핵심이며 승인된 실제 영상이 있음 | 화면의 의미를 본문·자막으로 설명. 정지 소재에 움직임만 붙여 시연처럼 보이게 하지 않음. 플랫폼마다 독자가 이해할 문맥으로 편집 |

승인된 영상은 Threads VIDEO + Instagram REELS, 스크린샷만 있으면 Threads IMAGE로 고정한다. 전송·변환 실패는 형식 변경 사유가 아니다. 그 범위에서 편집은 독자 가치 → 사실 근거 → 공개 허용 범위 → 필요한 미디어 가용성 → 실행 경로 → 참고할 계정 반응을 함께 보고 선택하라. 고정 비율·순환표·할당량을 만들지 마라. 한 사건을 여러 게시로 부풀리지 말고, 형식을 달리해도 같은 이야기라는 사실을 중복 검토에 반영하라. 처음부터 텍스트로 승인된 소재에서만 텍스트로 진행하고, 근거에 꼭 필요한 화면이 없으면 해당 주장만 보류하라.

## 공식 가이드의 적용 범위

2026-11-22 확인한 Meta Threads 교육 자료(2024-10-21, 페이지 갱신 2025-06-26)는 설명 텍스트가 있는 사진·영상·carousel의 평균 조회와 Threads에 맞춘 원본 콘텐츠를 다룬다. 이는 미디어에 문맥을 제공할 근거이며 모든 글의 영상화나 특정 계정의 노출 보장이 아니다. 답글 조회에 관한 통계는 대화 참여 맥락이므로 자기 후속 댓글 수를 늘리면 성과가 좋아진다는 근거로 사용하지 마라.

## 반응을 다음 소재에 반영

- 운영 정책의 점검 시점마다 실제로 접근할 수 있는 기존 게시 반응을 확인하라. 게시물 식별자·플랫폼·형식·게시 시각의 근거·관찰 시각·게시 후 경과 시간·지표 이름/값·조회 경로·조회 상태를 함께 받아라. 시각이나 지표가 없으면 unknown으로 유지하라.
- 새 보고의 누적 검토 기간과 게시 반응의 관찰 기간을 섞지 마라. 게시 전 자료 기간과 게시 후 반응 기간은 서로 다른 축이다.
- 수치와 실제 읽은 질문·오해·재현 피드백을 구분하라. 댓글 개수만으로 구체적 관심사나 독자 요구를 만들어내지 마라. 현재 도구가 댓글 본문을 읽지 못하면 정성 반응은 미확인으로 둬라.
- 같은 플랫폼 안에서도 형식·주제·게시 후 경과 시간이 다른 글은 한 번의 수치로 승패를 정하지 마라. 서로 다른 플랫폼 지표를 합산하거나 직접 비교하지 마라. 초기 게시 수가 적으면 방향을 탐색하는 기록으로만 사용하라.
- 조회 실패·결측·집계 지연을 0이나 반응 없음으로 바꾸지 마라. 반복 스냅샷의 누적 수치를 더하지 말고, 같은 정의·범위의 유효한 두 관찰만 차이를 계산하라.
- 다음 편집에서 바꿀 요소와 그 이유를 작게 정하라. 실제 질문이 있으면 그 궁금증을 새로운 근거로 설명할 소재를 검토하되 타인에게 자동 댓글을 달지 마라. 새 근거 없는 재게시나 이미 발행된 게시물 수정으로 반응을 조작하지 마라.

## 운영자 인계 메모

기존 단계·공개 범위 메모에 선택 형식·선택 이유·참고 출처와 한계·원자료 기간·사용할 미디어·읽은 반응의 근거를 덧붙여라. 연속 글은 원글과 각 후속의 추가 가치·순서·고정 작업 ID·의존 관계를 분리하라. 이는 비공개 운영 메모이며 원천 보고의 새 필드나 공개 글의 필수 양식으로 요구하지 마라.
